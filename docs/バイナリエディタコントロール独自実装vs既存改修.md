# バイナリエディタコントロール 独自実装 vs 既存改修 整理資料

## 1. 独自実装をしない理由

### 実装コストとリスクが非常に大きい
- 仮想化レンダリング・編集モデル・キャレット管理など、各要素が密接に絡み合う
- 実績のある既存実装でも長年のバグ修正が積み重なっており、ゼロから同等品質に達するまでに数ヶ月〜1年単位の工数がかかる
- 実装中に発覚する問題（大ファイル時のパフォーマンス劣化・DPI対応の崩れ等）が予測しにくく、スケジュールリスクが高い

### Be.Windows.Forms.HexBox は実績がある
- オープンソースとして長期間公開され、多くのプロジェクトで実使用されてきた実績がある
- 既知のバグや挙動は情報が蓄積されており、調査コストが低い
- ソースコードが公開されているため、改修・機能追加が可能な状態にある

### 改修は範囲を限定できる
- 独自実装は「全部作る」リスクを負うが、改修は不足している機能だけにスコープを絞れる
- 既存の動作品質を土台にするため、デグレードリスクをコントロールしやすい
- 改修箇所にテストを集中させることができる

### メンテナンス性の観点
- 独自実装は属人化しやすく、担当者が変わった際の引き継ぎコストが大きい
- Be.Windows.Forms.HexBox はソースが整理されており、第三者が改修箇所を理解しやすい
- 将来的に別の担当者が保守する際も、改修差分さえ管理すれば対応可能

### 補足：更新停止への懸念に対して
更新停止＝枯れた安定版と捉えることができ、仕様が固まっていて改修しやすい状態。
サーバーサイドのライブラリと異なり、UIコントロールとしてセキュリティリスクは生じにくく、安定性に問題はない。

## 2. 独自実装に必要な要素

### 一般的なカスタムコントロールに必要な要素
- **描画（Rendering）**：OnPaint をオーバーライドして自前描画。再描画の最小化も考慮が必要
- **入力処理**：キーボード・マウス・IMEのハンドリング
- **スクロール**：ScrollBar の組み込みとスクロール位置に応じた描画オフセットの計算
- **フォーカス・キャレット管理**：フォーカスの取得・喪失とカーソル位置の描画
- **サイズ変更対応**：ウィンドウリサイズ時の再レイアウト計算

### バイナリエディタ専用に追加で必要な要素
- **2ペイン構造の同期**：HexペインとASCIIペインのカーソル位置を常に同期させる
- **ニブル単位のカーソル**：1バイト＝2桁（上位/下位4bit）単位でのカーソル状態管理
- **巨大ファイルへの対応（仮想化）**：表示領域分だけデータを読み込み、スクロールに応じて動的に切り替える
- **編集モデル**：Piece Table 等の専用データ構造による挿入・削除の効率化
- **Undo/Redo**：編集履歴の管理とメモリ効率の考慮

## 3. バグが出やすい箇所

| 箇所 | バグの出やすさ | 主な原因 |
|---|---|---|
| ニブルカーソル境界 | ★★★★★ | 状態の組み合わせが多い |
| 選択範囲の描画 | ★★★★☆ | 逆方向選択・複数行 |
| 編集の境界値 | ★★★★☆ | 先頭・末尾・空ファイル |
| Undo/Redo の整合性 | ★★★★☆ | 複合操作の考慮漏れ |
| DPI スケーリング | ★★★☆☆ | 環境依存 |
| スクロール同期 | ★★★☆☆ | オフセット計算ミス |
| クリップボード | ★★★☆☆ | 形式の解釈の曖昧さ |

### 各箇所の詳細

#### ニブル単位のカーソル移動
- 1バイトの上位/下位ニブルをまたぐ操作の境界処理
- バイト境界をまたぐ選択状態の管理
- **バグ例**：末尾バイトの下位ニブルにカーソルがある状態で右キーを押すと、カーソルが範囲外に飛ぶ

#### 選択範囲の描画
- 複数行にまたがる時の矩形ハイライト計算
- HexペインとASCIIペインのハイライトのずれ
- **バグ例**：末尾から先頭方向にドラッグ選択すると、ハイライトが正しく描画されない

#### 編集操作の境界値
- ファイル先頭・末尾・空ファイルでの操作が最もバグが出やすい
- **バグ例**：0バイトのファイルを開いた状態で入力すると例外が発生する

#### Undo/Redo の整合性
- 連続した編集をまとめてUndoした時のデータ破損
- 貼り付けなど複合操作後のUndo
- **バグ例**：貼り付け→Undo→別の操作→Redoで、データが元に戻らない

#### DPI スケーリング
- 96DPI で開発・テストすると高DPI環境でレイアウトが崩れる
- **バグ例**：高DPI環境でASCIIペインの文字がHex列と1文字分ずれる

#### スクロールとレンダリングの同期
- スクロール位置とデータオフセットの対応ずれ
- **バグ例**：ファイル末尾付近でスクロールすると、存在しない行が描画される

#### クリップボード操作
- HexペインとASCIIペイン間での貼り付け時の形式解釈の曖昧さ
- クリップボードに想定外の形式のデータが入っている時の例外処理
